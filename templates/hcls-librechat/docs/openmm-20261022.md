# OpenMM in the Scientific AI Workspace

The `openmm` skill uses the hosted OpenMM 8.6.1 App through its published
`submit_openmm_workflow` MCP tool. The equivalent REST entry point is
`POST /v1/models/openmm:submit`; inspect `GET /v1/models/openmm` for the current
parameters and artifact-upload contract. Use the existing Scientific AI key,
not an operator credential. Availability and permissions come from the live
authorized catalog, not from installing this skill.

## Try a reproducible example

> Use the OpenMM skill. Create the public solvated alanine example in a new
> workspace directory. Minimize it, equilibrate at 300 K and 1 bar, and run
> 0.1 ns of production with a 2 fs timestep. Submit once, keep the saved workflow
> running, and show the verified structure and timing report inline when done.
> Keep all inputs, seeds, checkpoints and trajectory files in my workspace.

The skill's `scripts/make-example.py` creates hash-pinned alanine, villin protein
or GROMACS ionic example packs without submitting work. For example:

```bash
python3 /app/skill/openmm/scripts/make-example.py \
  --example alanine --backend cuda --steps 50000 \
  --output /workspace/my-studies/openmm-alanine --starter-pack
```

The generated `parameters.json`, `input.tar.gz` and `provenance.json` are
reproducible inputs. The optional starter recipe is under
`molecular-dynamics/alanine/`. Output belongs in a different directory from
the immutable starter data. The system examples bucket also retains
`examples/openmm-v1/{alanine,protein,ionic}/`; this is not a claim that every
existing customer's bucket has been overwritten or reseeded.

## Scientific scope

- PDB/mmCIF with bundled OpenMM force fields; optional hydrogens and explicit
  solvent. Ligand parameters must already be valid for the chosen force field.
- Prepared Amber PRMTOP + INPCRD/RST7 or GROMACS TOP + GRO, including all includes.
- Explicit minimization, Langevin-middle NVT/NPT or Verlet phases, seeds,
  timestep, constraints, output intervals and optional hydrogen-mass repartitioning.
- CUDA by default; explicit CPU execution is separate and never a silent fallback.

The App does not execute arbitrary Python, uploaded force-field scripts, custom
serialized System/Integrator objects, enhanced-sampling plugins, replica
exchange or multi-GPU protocols. A successful short example is not a
convergence, force-field equivalence or production-capacity measurement.

## Results and continuation

Native results contain structures, DCD trajectories, state CSV, binary
checkpoints, portable State XML, logs and file hashes. `structure.cif` is the
authoritative topology for visualization; PDB is optional when representable.
`trajectory-frames.jsonl` records each DCD frame's absolute step and time.
Segments shorter than their report interval can legitimately have no DCD frames;
final State and coordinates are still saved.

Use the existing operation's resume action after interruption. Compatible binary
checkpoints retain internal state; cross-device portable State restores physical
state, not RNG history or a bitwise-identical stochastic trajectory. This is
native MD checkpointing, **not GPU process snapshotting**. Do not resubmit an
accepted job or rerun simulation merely to retrieve or render its results.

The existing native-MD preview helper produces the inline timing report and
final-coordinate view from verified outputs. Measured ns/day excludes startup,
queueing and delivery; all are separate timings. Unknown values are not zero.
